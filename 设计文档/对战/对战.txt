核心领域模块：【对战系统】(Combat Engine & Battle Timeline)

第一章：对战状态机与时钟阶段流转 (Battle State Machine & Phase FSM)

对战系统是连接【卡牌】、【效果】、【人物】与【职业】的中央时钟与调度总线。

系统采用严格的**确定性分相状态机（Phase-Driven Deterministic
FSM）**驱动，保证整个战斗流程在无画面（Headless）状态下可在数毫秒内完成推演，并支持跨端 100% 精确复现。

1.1 完整对战时序阶段定义与执行职责

一场对战从开始到结束，严格依序流经以下 8 个标准阶段：

1. 【BattleInit 相】（战斗初始化）

  - 空间布局：加载玩家实体、友方召唤物初始槽位、从【地区】怪物池拉取敌人并完成战场坐标排布；
  - 牌库初始化：加载玩家牌组（10张基础+爬塔获取卡牌），绑定 RNG_Deck 子随机数流执行 Fisher-Yates 初始洗牌，灌入【抽牌堆】；
  - 规则注入：挂载玩家选定的 3~5 个局外大天赋、玩家持有的全量【遗物】与怪物固有被动；
  - 广播 Hook：触发全局 OnCombatInit 与 OnCombatStart。

2. 【RoundStart 相】（大轮开始）

  - 时钟推进：大回合计数器 \text{RoundCount} \leftarrow \text{RoundCount} + 1；
  - 环境结算：触发战场环境词缀（如高难天气、全场光环）；
  - 狂暴时钟检测：判定 Boss 是否触达软狂暴回合线（如 \text{Round} \ge 12 时激活狂怒增伤）。

3. 【PlayerTurnStart / PlayerAction 相】（玩家主操作阶段）

  - 时钟切分与护甲重置：
      - 触发 OnPlayerTurnStart；
      - 护甲衰减：玩家身上的当前护甲（Block）清零（除非拥有【巨岩躯体】或【永恒之壁】大天赋）；
      - 能量填充：能量池重置至基础上限（默认 3 点）；
      - HOT 状态跳字：按层数结算玩家及全队身上的【滋养】持续回血，随后层数 -1；
      - 职业专属自产：愈合流按指数阶梯自产种子、神射手光能衰减 -15、狂战士炎魔判定；
      - 意图推导展示：调用全场怪物的 AI 决策树，在敌人头顶明牌渲染下一动意图（攻击数值/防御/Debuff）。
  - 抽牌入手机制：
      - 从抽牌堆顶抽取卡牌至手牌区，触发 OnCardDrawn；
      - 手牌硬上限 5 张控制：若抽牌导致手牌数 >5，多余卡牌直接转入弃牌堆。
  - 玩家自由出牌循环（Action Loop）：
      - 接收玩家出牌指令 \rightarrow 校验费用与目标合法性 \rightarrow 扣除能量 \rightarrow 压入动作队列
        \rightarrow 执行卡牌动作树 \rightarrow 触发胜负即时检测；
      - 循环往复，直到玩家主动点击“结束回合”按钮，或触发强制结束回合机制（如打满 4 张牌被深渊巨兽打断）。

4. 【AllyAction 相】（友方随从/构造物行动阶段）

  - 时序定位：玩家回合刚刚结束、敌人出手前的绝对安全窗口期。
  - 按槽位从左至右顺序执行：
      - 实体随从（野狼/树人）：依次发动撕咬或反伤护卫，造成伤害并触发吸血反哺；
      - 环境构造物（水龙卷/音箱）：水龙卷消耗 15 寒冰能量进行随机多段轰击；
      - 灵体协同物（月刃/战隼）：进入休眠待命态，等待下轮玩家打牌触发追击。

5. 【EnemyAction 相】（敌人群体行动阶段）

  - 按敌人站位索引（Slot 0 \rightarrow Slot 4）依次出招：
      - 清除该敌人身上的上一轮护甲；
      - 执行该敌人头顶已明牌预告的【意图动作树】（如多段攻击、群体上易伤、召唤小怪）；
      - 每次攻击命中玩家，依次穿透【五阶段数值计算管道】（触发神盾 50% 吸收、反震反伤、狂战士血气积累）；
      - 出招完毕，该敌人意图清空，播放收招待命动画。

6. 【RoundEnd 相】（大轮回合结算阶段）

  - DOT 异常跳字：依次结算全场所有单位身上的【燃烧】真实伤害，随后燃烧层数 -1；
  - Buff 周期衰减：全场单位身上的【易伤】、【虚弱】、【冻结】、【锐利】持续时间或层数 -1；
  - 手牌清理：玩家手牌区未保留的卡牌全量移入【弃牌堆】；
  - 胜负裁决：
      - 若全场 [Enemy] 标签单位全部阵亡 \rightarrow 跳转 BattleVictory；
      - 若玩家本体生命 \le 0 且无免死可用 \rightarrow 跳转 BattleDefeat；
      - 若双方均存活 \rightarrow 回到 RoundStart 开启下一大轮。

第二章：确定性命令队列与无头解耦架构 (Command & Action Queue)

为了保证游戏在网页端与手机端绝对不卡顿、无死锁，且逻辑层可在 CLI 终端以 10000
局/秒的速度进行无头跑测，逻辑与表现层采用“命令执行队列（Command
Execution Queue）”单向驱动。

┌───────────────────────────────────────────────────────────────────────────────────┐
│                           1. 逻辑核：瞬间无锁推进 (Core Engine)                    │
│   玩家发出出牌指令 ──► 逻辑帧 0 毫秒完成五阶段数值与状态结算 ──► 提交快照至状态机    │
└─────────────────────────────────────────┬─────────────────────────────────────────┘
                                          │ 派发结构化渲染指令 (Render Directives)
                                          ▼
┌───────────────────────────────────────────────────────────────────────────────────┐
│                           2. 表现层：异步平滑动效管线 (View Sequencer)             │
│   [卡牌飞出] ──► [受击震屏/飘字] ──► [飞叶/雷电粒子绽放] ──► [血条平滑补间扣减]   │
│   (表现层播放完一组动效后，向逻辑核发送 OnAnimationComplete 回调，拉取下一指令)    │
└───────────────────────────────────────────────────────────────────────────────────┘

1. 原子动作队列执行规则（Action Dispatcher Rules）

  - 先进先出（FIFO）排队机制：任何连环触发的连锁动作（如：攻击 \rightarrow 触发反伤 \rightarrow 触发受击反哺
    \rightarrow 触发抽牌 \rightarrow 触发抽牌打雷），所有子动作按产生顺序依次追加至 ActionQueue 末尾；
  - 原子级隔离：前一个动作未完成内部状态提交前，后一个动作严禁读取脏数据，杜绝并发竞态条件；
  - 快照提交点（State Commit）：每一个原子动作执行完毕，向 View 层派发
    DeltaStateSnapshot（血量差量、Buff增减、牌堆变动），表现层据此驱动 UI 动画。

第三章：战场空间拓扑与槽位坐标系统 (Battlefield Grid)

为了让移动端小屏幕上的敌我单位排布井然有序，系统采用离散网格槽位系统（Discrete Grid Slots），杜绝坐标穿模。

+-----------------------------------------------------------------------------------+
| 敌方阵地 (Enemy Grid: 5 槽位)                     玩家与随从阵地 (Player Grid: 4 槽位)|
+-----------------------------------------------------------------------------------+
|                                                                                   |
|  [Slot 4: 后排]  [Slot 2: 中排]                   [Slot 3: 构造物] (舞台音箱/水龙卷)|
|                                                   [Slot 2: 后排随从] (林精花仙)     |
|  [Slot 3: 后排]  [Slot 1: 前排]  ◄──── 对峙 ────► [Slot 1: 前排随从] (远古树人/野狼)|
|                                                   [Slot 0: 玩家本体] (角色核心)     |
|  [Slot 0: 首领/单体核心]                                                          |
|                                                   [空中槽位: 悬浮] (悬浮月刃/空中战隼)|
+-----------------------------------------------------------------------------------+

1. 目标索敌优先级规则（Targeting Priority Protocol）

  - 近战攻击判定：未携带 [Ranged(远程)] 或 [Pierce(贯穿)]
    标签的常规单体近战攻击，默认必须优先命中前排槽位（Slot 1）的实体；前排存活时，无法直接攻击后排；
  - 穿透与顺劈判定：带有 [顺劈/溅射] 的技能命中目标后，自动向该槽位垂直相邻的 Slot $\pm 1$ 单位传导 30%~60% 的次级伤害；
  - 全场 AOE 判定：直接对阵地上所有激活状态的槽位实体并发派发独立伤害动作。

第四章：胜负判定、斩杀与事务级存盘系统 (Persistence & Anti-SL)

4.1 绝对确定性单局录像协议（Deterministic Replay Protocol）

为了支持跨平台反作弊校验与战斗回放，整场战斗在底层仅由 初始种子 + 输入指令流 构成：

\text{BattleReplay} = \left\{ \text{MasterSeed}, \text{ClassID}, \text{InitialDeck[]}, \text{Keystones[]}, \left[ \text{Command}_0, \text{Command}_1, \dots, \text{Command}_N \right] \right\}

  - 每一个 Command 仅记录：{ FrameIndex, PlayerActionType, SourceCardInstanceID,
    TargetSlotIndex }；
  - 工程价值：单场战斗的录像文件体积 < 2 \text{ KB}，极易上传云端或保存在本地，支持无头服务器以毫秒级时间完成反作弊跑测校验。

4.2 事务级双槽快照存盘（Double-Buffer Save Commit）

针对 Web 端 / 移动端容易发生“误触刷新（F5）、杀后台、手机断电”等异常退出场景，设计了事务级持久化机制：

[玩家打出卡牌 / 回合结束] ──► [动作队列结算至静止态] ──► [序列化 BattleState 为 JSON]
                                                              │
                                                              ▼
[写入 IndexedDB / LocalStorage 备用槽: Slot_B] ◄── [LZ-String 极限压缩 (体积缩减 90%)]
              │
              ▼ (校验 Checksum 哈希码无损)
[原子切换主槽指针: ActiveSlot = Slot_B] ──► [释放 Slot_A 旧数据]

  - 防 SL（存读档刷牌）机制：
      - 由于抽牌流严格绑定 RNG_Deck，玩家无论在战斗中强行刷新页面重开多少次，重开后每一回合摸到的手牌顺序、怪物的暴击与随机判定 100%
        完全相同，彻底封死 SL 刷好运漏洞；
      - 若玩家在怪物出招结算中途中断，重新进入游戏时，系统自动回滚至本回合开始前的确定性提交点，保证存档绝对零损坏。

第五章：Web / 移动端表现层时钟与动效解耦 (Animation Sequencer)

表现层（Pixi.js / DOM）与底层逻辑核之间通过**动效时钟解耦器（Animation Sequencer）**协调：

                    ┌─────────────────────────────────────────┐
                    │      逻辑核: 瞬时生成渲染指令流         │
                    └────────────────────┬────────────────────┘
                                         │
                 ┌───────────────────────┴───────────────────────┐
                 ▼ (常规对战模式: 1.0x 速率)                     ▼ (极速/跳过模式: Turbo / 2.0x)
      ┌──────────────────────┐                        ┌──────────────────────┐
      │  标准 Tween 补间动效  │                        │  极速跳字与瞬间到位  │
      │ - 卡牌划出抛物线 (0.2s)│                        │ - 缩短动效时间至 30% │
      │ - 受击震屏与红闪 (0.15s)│                       │ - 粒子特效并发消化   │
      │ - 飞叶/雷暴粒子 (0.3s)│                        │ - 保证手机端操作极速 │
      └──────────────────────┘                        └──────────────────────┘

  - 视口操作锁定（Input
    Blocker）：当动作队列处于“大招连击动效播放中”时，表现层自动挂起手牌区的触控事件，防止玩家在动效未播完前高频连点导致视觉层混乱；
  - 动画合并优化（Visual Merging）：当多段连击（如狂战士【迷狂炎舞】3连击、神射手【暴风箭矢】12连射）触发时，表现层自动将 12
    个独立飘字合并为“跳字瀑布”，防止手机端发生 GPU 掉帧。
