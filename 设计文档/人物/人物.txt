核心领域模块：【人物与实体系统】(Character & Entity Architecture)

整体系统架构与六大分类全景

在战斗引擎中，战场上的所有生命体与作战单位统一抽象为 UnitEntity 基础实体。系统将其解构为 6 个核心大类 进行高度模块化设计：

│   [属性容器: HP / 护甲 / 屏障] │ [状态集: BuffRepository] │ [标签矩阵: TagMatrix] │
└─────────────────────────────────────────┬─────────────────────────────────────────┘
                                          │ 派生六大实体大类
                                          ▼
┌───────────────────────────────────────────────────────────────────────────────────┐
│ 1. 【玩家主角实体】(Player)    : 绑定能量池、手牌堆、职业专属仪表盘与局外大天赋     │
│ 2. 【友方随从/召唤物】(Allies)  : 远古树人、森林野狼、舞台音箱、悬浮月刃、水龙卷   │
│ 3. 【普通怪物实体】(Monsters)  : 基础小怪，遵循固定意图循环或概率轮盘 AI           │
│ 4. 【精英怪物实体】(Elites)    : 拥有反伤光环、狂暴机制与特定流派克制能力的高危单位 │
│ 5. 【首领 Boss 实体】(Bosses)  : 多阶段转换（Phase Shift）、锁血硬免死与动态意图树 │
│ 6. 【数据 Schema 与 AI 契约】 : 统一 JSON 配置表与 AI 行为树 DSL 规范              │
└───────────────────────────────────────────────────────────────────────────────────┘

大类一：底层统一实体抽象与生命周期 (UnitEntity Core)

战场上的任何作战单位（玩家、野狼、Boss、音箱）在底层均拥有完全一致的物理属性契约，保证数值计算管道与 Buff 挂载逻辑 100% 通用。

┌───────────────────────────────────────────────────────────────────────────────────┐
│                             统一实体基础属性容器                                  │
├───────────────────────────────────────────────────────────────────────────────────┤
│ • 生命三层结构: 当前生命 (CurrentHP) / 最大生命 (MaxHP) / 临时屏障 (Barrier)       │
│ • 防御双层结构: 当前护甲 (CurrentBlock) / 绝对减免系数 (DamageReductionRatio)     │
│ • 状态寄存器:   BuffRepository (挂载力量、易伤、燃烧、滋养等 Buff 实例字典)       │
│ • 实体标签库:   Tags[] (如: [Player], [Enemy], [Summon], [Construct], [Boss])    │
│ • 空间与朝向:   SlotIndex (战场槽位 0~5) / Facing (Left/Right)                     │
└───────────────────────────────────────────────────────────────────────────────────┘

统一实体生命周期状态机（Lifecycle FSM）

1.  Spawn（入场阶段）：初始化基础血量与槽位坐标 \rightarrow 触发全局 Hook OnUnitSpawned \rightarrow
    挂载入场 Buff/光环。
2.  Active（行动阶段）：回合开始结算【滋养/燃烧】 \rightarrow 执行意图动作或等待玩家输入 \rightarrow 护甲衰减判定。
3.  Damage & Reaction（受击阶段）：流经五阶段数值管道 \rightarrow 扣减屏障 \rightarrow 扣减护甲
    \rightarrow 扣减生命 \rightarrow 广播 AfterDamageReceived。
4.  Fatal Check（致死拦截）：生命 \le 0 时，触发 OnFatalDamageTaken 拦截（判定是否触发免死、碎冰涅槃或名刀）。
5.  Death & Despawn（死亡销毁）：广播 OnUnitKilled（触发击杀收益） \rightarrow 播放死亡/瓦解动画
    \rightarrow 移出战场活跃实体列表 \rightarrow 释放内存。

大类二：玩家主角实体模型 (Player Character Entity)

玩家实体继承自 UnitEntity，具备统领整场战斗、接收人机交互指令与承载局外构筑的专属组件：

┌───────────────────────────────────────────────────────────────────────────────────┐
│                             【玩家主角实体】专属组件                               │
├───────────────────────────────────────────────────────────────────────────────────┤
│ 1. 牌区管理器 (PileManager)       : 严格管控 抽牌堆 / 手牌区(上限5) / 弃牌堆 / 放逐堆│
│ 2. 能量中枢 (EnergyManager)       : 当前能量 / 初始能量(3) / 临时过载能量           │
│ 3. 专属资源池 (ClassResourcePool) : 动态驱动 种子(0~99) / 雷印 / 玄冰 / 魂槽 / 怒气 │
│ 4. 局外大天赋挂载器 (KeystoneHost): 注入战前装配的 3~5 个规则重塑大天赋 Hook       │
│ 5. 经济与单局数据 (RunDataContext): 局内金币 / 爬塔层数 / 战利品掉落保底计数器      │
└───────────────────────────────────────────────────────────────────────────────────┘

  - 玩家回合执行流：
      - RoundStart \rightarrow 恢复初始能量（3点） \rightarrow 触发职业自产资源（如愈合流自产种子、光能衰减）
        \rightarrow 从抽牌堆抽取 5 张手牌 \rightarrow 挂起等待玩家出牌指令 \rightarrow 玩家点击“结束回合”
        \rightarrow 进入敌人行动阶段。

1. 实体战斗随从（Active Minions - 如：远古树人、森林野狼）

  - 物理特征：占用战场前排槽位（Slot 1~2），拥有独立的血条（HP）、护甲（Block）与受击判定。
  - 交互规则：
      - 能承受伤害：敌人单体攻击会优先被前排随从阻挡（承担护卫肉盾职能）；
      - 能接受治疗与 Buff：森语者的【滋养】与【生命绽放】可精准对其释放，并触发随从被动（如受治疗增加攻击力）；
      - 自动行动时钟：在玩家回合结束、敌人行动前，按顺序自动发动攻击（如野狼撕咬造成 6 点撕裂伤害）。

2. 战场功能构造物（Field Constructs - 如：舞台音箱、灭世水龙卷）

  - 物理特征：占用战场后排或特定环境槽位，无生命值概念（免疫任何攻击），按持续回合数或特定能量（如寒冰能量）维持存在。
  - 交互规则：
      - 动作回响广播：乐手打出技能时，舞台音箱以 60% 效率在战场另一侧镜像广播一次治疗或音波；
      - 环境自律攻击：水龙卷每回合自动扣除 15 点寒冰能量，并在回合开始时对敌方随机轰击 3 次。

3. 悬浮空中灵体（Floating Spirits - 如：悬浮月刃、空中战隼）

  - 物理特征：悬浮于玩家本体身侧或天际，完全无法被敌人选中（无敌态）。
  - 交互规则：
      - 协同触发（On-Hit Procs）：不占用独立行动回合。当玩家打出攻击牌时，月刃立即发动追击；当玩家打出暴击时，战隼立即俯冲撕裂目标。

大类四：普通怪物与精英怪体系 (Monsters & Elites)

怪物系统的设计哲学是：“行为绝对明牌化（Transparent Intent），将确定性留给敌人，将解题策略留给玩家。”

┌───────────────────────────────────────────────────────────────────────────────────┐
│                             怪物意图推导引擎 (Intent Engine)                      │
├───────────────────────────────────────────────────────────────────────────────────┤
│ 1. 意图类型 (Intent Types)   : 纯物理攻击 / 多段连击 / 叠加护甲 / 施加Debuff / 蓄力大招 │
│ 2. 意图解析时钟 (Timing)     : 在【玩家回合开始前】完成推导，头顶精确显示伤害与段数 │
│ 3. AI 决策树模型 (Behavior) : 固定循环序列 (Loop) / 动态概率轮盘 / 条件分支 (Branch)│
└───────────────────────────────────────────────────────────────────────────────────┘

4.1 怪物四大 AI 决策模型

所有非 Boss 怪物必须基于以下 4 种行为树逻辑之一配置：

1. 固定循环模式 (Deterministic Loop) : [攻击 8点] ──► [叠甲 6点] ──► [易伤 2层] ──► (回到第一步)
2. 动态概率轮盘 (Weighted Roulette)  : 60% 概率普通攻击，25% 概率重击，15% 概率加防御 (防连续重击)
3. 血量阈值分支 (HP Threshold Branch) : 生命值 > 50% 时持续狂暴攻击；生命值 <= 50% 时进入狂化自愈
4. 响应式被动反制 (Reactive Reaction) : 玩家本回合每打出一张牌，怪物头顶意图伤害提升 2 点

4.2 精英怪（Elites）核心设计法则

精英怪拥有改变单局战斗逻辑的**“规则级被动”**，用于检验玩家卡组的综合攻防合格度：

| 精英怪代号         | 核心被动机制                                  | 意图与杀招                   | 考验玩家的卡组维度                         |
| :------------ | :-------------------------------------- | :---------------------- | :-------------------------------- |
| **【荆棘狂暴巨兽】**  | **反震尖刺**：每次受到攻击伤害，立即反震攻击者 3 点真实伤害。      | 每 3 回合蓄力释放一次 35 点毁灭重砸。  | 考验卡组的“单发高伤爆发”能力（克制低伤多段刮痧流）。       |
| **【深渊灵魂编织者】** | **时间锁链**：玩家单回合打出超过 4 张卡牌时，强制结束玩家回合。     | 持续给玩家手牌中塞入【虚妄寄生（抽到扣血）】。 | 考验卡组的“单卡质量与费用效率”（克制无限 0 费刷牌流）。    |
| **【贪婪掠夺甲虫】**  | **硬化岩甲**：单次受到的攻击伤害上限锁死为 15 点（超过部分强制无效）。 | 携带大量护甲，且每回合攻击力永久递增 3 点。 | 考验卡组的“多段攻击、DOT 燃烧/流血”能力（克制单发核爆流）。 |

5.1 商业级 Boss 三大通用防御机制（Anti-Degeneracy）

为防止玩家神仙构筑（如 99 种子/一闪无限流）在一回合内将 Boss 瞬间秒杀导致体验崩塌，Boss 系统内置三大防御规则：

1.  阶段锁血（Phase Transition Gate）：
      - 在一阶段未结束前，单次超高额伤害最多只能将 Boss 血量扣减至阶段分界线（如 50%），超过的伤害被神圣护盾强制吸收，随后进入阶段转换演出。
2.  伤害单次吸收上限（Damage Cap Per Hit）：
      - Boss 单次受到的伤害不可超过其最大生命值的 25%（防止数值溢出 BUG 一击秒杀）。
3.  动态狂暴时钟（Soft Enrage Timer）：
      - 战斗超过 12 个回合后，Boss
        获得【绝对狂怒】：造成的伤害每回合提升 50%，逼迫纯防守自愈流派（如愈合流、光盾流）必须拥有终结手段，杜绝无限拖时间。
